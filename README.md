# DesktopSecretary_v0.1

> 框架重构版：面向 LLM + SQLite + 桌面秘书 Agent 的第二阶段探索。

这个仓库是 `DesktopSecretaryDemo` 之后的框架重构版本。相比早期 Demo，这一版不再只关注“桌宠 + 聊天”的体验，而是尝试把项目重构成一个更像桌面 Agent 的系统：LLM 负责理解意图和生成结构化调用，本地 SQLite 负责保存任务和数据，桌面角色负责承载交互、提醒和陪伴体验。

## 重构目标

- 从原型脚本转向模块化框架。
- 从简单聊天转向工具调用式 Agent。
- 从 JSON/临时缓存转向 SQLite 本地数据管理。
- 从被动对话转向主动提醒、专注检测和日程协助。
- 从单一 UI 转向插件化窗口和模块管理。

## 核心能力

### 1. LLM 请求框架

项目封装了网络请求层，用于发送 OpenAI-compatible / DeepSeek-compatible Chat Completion 请求。

LLM 不只负责生成普通回复，也会通过工具调用返回结构化结果，例如：

- 生成 SQL 查询
- 生成任务增删改语句
- 生成带情绪的角色回复
- 判断用户是否专注
- 生成长期记忆摘要

### 2. SQLite 本地数据库

重构版引入了更明确的本地数据库管理层，用于管理任务、日程和后续记忆数据。

已实现能力包括：

- 从 `StreamingAssets` 初始化数据库到 `persistentDataPath`
- 读取 SQLite 表数据并缓存为 C# 对象
- 执行 LLM 生成的 SQL
- 支持 SELECT 查询结果回传给 LLM
- 支持 CRUD 操作和 undo SQL 记录
- 驱动日程 UI 更新

### 3. LLM + SQL Agent 链路

这一版的核心探索是让 LLM 根据用户自然语言生成 SQL，再由本地系统执行。

示例流程：

1. 用户输入：“帮我添加明天上午十点的会议任务”
2. LLM 识别为任务创建意图
3. LLM 通过工具调用生成 SQLite INSERT 语句
4. 本地 DBSourceManager 执行 SQL
5. 日程模块刷新任务数据
6. 桌面秘书给出自然语言反馈

这比早期 Demo 的“LLM 直接生成文本”更接近 Agent 工作流。

### 4. 长期记忆

重构版开始引入长期记忆机制：

- 保存聊天历史
- 读取最近 24 小时对话作为上下文
- 生成关键记忆
- 将长期记忆注入后续系统提示词
- 结合好感度、角色状态影响回复

目前记忆机制仍处于探索阶段，后续可以进一步升级为 SQLite 表、向量检索、记忆重要度衰减和可编辑记忆系统。

### 5. 桌面秘书体验

项目仍然保留桌面秘书/桌宠方向，包括：

- Live2D / 动画状态
- 情绪驱动回复
- 语音合成与播放
- 桌面窗口管理
- 日程提醒
- 专注检测
- FairyGUI 界面模块

## 阶段总结

这个版本是从“桌宠 Demo”走向“桌面 Agent 框架”的过渡版本。

它的主要成果不是 UI 完成度，而是验证了几条关键技术路线：

- LLM 可以作为自然语言到本地操作的转换层。
- SQLite 可以成为本地任务、日程和记忆的基础数据层。
- Tool Calling 可以把聊天助手升级为能执行本地操作的 Agent。
- 桌面秘书可以将日程、专注、记忆和角色陪伴整合到一个入口中。

## 后续计划

下一阶段计划重新开仓库进行更大规模重构，目标是构建一个真正可长期维护的桌面秘书系统：

- 更清晰的 Agent Core
- 更安全的 SQL 执行层
- 独立记忆系统
- 插件化工具系统
- 日程与开发任务协同
- 更稳定的桌面窗口和角色表现
- 更完整的配置、日志和调试工具

这个仓库作为第二阶段探索保留，用于展示从原型到框架化的演进过程。
